Help

1. Introduction

DoNotNotify is an Android app designed to cut down the number of notifications from other apps on your device. While the Android OS itself does offer the ability to block all notifications from apps, or block them from specific channels (if the app has been programmed correctly), this often does not suffice. Most apps still do not use channels correctly (if at all), and DoNotNotify takes a different approach to notification blocking — by specifying rules that block, allow, stack or throttle individual notifications depending on the source app and their content.

Everything happens on your phone. DoNotNotify has no servers and needs no internet access.

2. Getting started

The first time you open DoNotNotify, a short setup walks you through what it needs:

  • Notification access, so it can see your notifications and act on them according to your rules.
  • Unrestricted battery use, so Android doesn't put it to sleep in the background.
  • Autostart, on phones whose manufacturer adds its own background restrictions (Xiaomi, Samsung, OnePlus and others). The setup opens the right settings screen where it can.
  • Permission to post notifications (Android 13 and newer), which Stack rules need.

After that, DoNotNotify checks every so often that it is still running. If your phone shuts it down, you'll get a "DoNotNotify isn't running" notification; tap it to turn it back on.

3. Creating a rule

The easiest way to create a rule is from a notification you want to deal with. In the "History" tab, tap the notification, then tap Create Rule. The rule wizard opens with the app, title and text already filled in. You can also start from scratch with Add a New Rule in the "Rules" tab, and pick the app first.

The wizard then asks for:

  • A rule type: Denylist, Allowlist, Stack or Throttle (see below).
  • Filters for the notification's title and text. As you type, DoNotNotify shows the latest notification from that app that your filters match, with the matching part highlighted, and how many of the app's recent notifications they match. Leave both filters empty to cover everything the app sends.
  • A review of the rule. From here, Advanced Configuration lets you limit when the rule applies, and set a Throttle rule's wait time.

To change a rule later, tap it in the "Rules" tab. There you can change its type and filters, turn it off in Advanced Configuration, or delete it. Each rule shows how many notifications it has matched ("Hits"), plus a small icon for each condition it has. The All rules active switch at the top of the tab turns every rule off or on at once.

4. Denylist, Allowlist, Stack & Throttle

Every rule has one of four types:

  • Denylist — matching notifications are blocked. Everything else from the app comes through.
  • Allowlist — matching notifications come through, and all other notifications from the app are blocked. If an app has several Allowlist rules, a notification that matches any of them comes through.
  • Stack — nothing is blocked. Instead, matching notifications are removed from the source app and re-posted by DoNotNotify as a single grouped notification — one summary entry you can expand to see the individual items. It's ideal for chatty apps you don't want to silence entirely: you keep all the information, but as one tidy, collapsible entry instead of a constant stream.
  • Throttle — the first matching notification comes through, and repeats are blocked for a while (see Throttle rules below).

If a notification matches both a Denylist and an Allowlist rule, the Denylist rule wins and it is blocked. Stack and Throttle rules never block the app's other notifications.

On Android 13 and newer, stacking needs DoNotNotify's own notification permission — the setup asks for it, and any Stack rule will show an inline warning with a one-tap fix if it has been turned off. Once a Stack rule is saved, Sound and vibration in its Advanced Configuration opens Android's settings for that stack, so you can, for example, make it silent.

5. Match types: Contains vs. Regex

Each filter (title and text) has a match type toggle below it: Contains or Regex. A notification has to match both filters; an empty filter matches anything.

Contains (the default) is a simple case-insensitive substring check — the notification field just needs to include the text you typed, anywhere. For example, the filter promo will match "Big Promo Deal" or "PROMO Code".

Regex lets you use a regular expression for more precise matching. The pattern is matched against the field in the same way as the Unix grep command — it searches for the pattern anywhere in the field, and the match is case-sensitive by default. A few practical examples:

  • ^- — matches any title that starts with a hyphen. Useful if you name calendar tasks like -taskname to flag them for blocking.
  • \d{6} — matches any title containing a 6-digit number. A quick way to catch OTP / verification code notifications.
  • (?i)sale — case-insensitive match for "sale" (the (?i) prefix enables case-insensitive mode for the whole pattern).
  • \Aprice drop\z — matches only the exact text "price drop" with nothing before or after. Use \A and \z when you need a strict whole-field match.

The ^ anchor matches the start of the field and $ matches the end (note: $ also matches just before a trailing newline, so use \z if you need a truly strict end-of-field anchor). The rule wizard won't let you continue with a pattern that has a syntax error. If one gets saved while editing a rule, that rule simply never matches — so if a regex rule does not seem to be working, double-check the pattern for typos.

6. Limiting when a rule applies

By default a rule is always on. To limit it to certain times or situations, tap Advanced Configuration in the rule editor, or on the last step when creating a new rule. Under Only apply when, you can turn on either or both of these conditions:

  • Time of day — the rule only applies between a start and an end time, including both ends. The window can cross midnight: 22:00 – 07:00 covers the whole night.
  • Phone usage — the rule only applies while the phone is In use (screen on and unlocked), or only while it is Not in use (screen off, on the lock screen, or showing the always-on display). DoNotNotify checks this at the moment each notification arrives.

If you turn on both, both must hold. Rules with a condition show a small icon for it in the Rules list.

When a rule's conditions don't hold, DoNotNotify ignores that rule completely. This matters most for Allowlist rules: outside its conditions, an Allowlist rule does not block the app's other notifications, so the app behaves as if the rule didn't exist.

A couple of examples:

  • A Denylist rule for a chat app with Phone usage: In use keeps its notifications from popping up while you watch a video or show someone a photo. When the phone is idle, they come through as normal.
  • An Allowlist rule that only lets through messages from one person, set to Time of day: 22:00 – 07:00, gives you a quiet night with one exception. During the day, every notification from that app comes through.

Blocked notifications are not delivered later when a condition stops holding, but you can always find them in the "Blocked" tab.

7. Throttle rules

Some apps send the same kind of notification over and over within seconds, like a navigation app counting down the distance to a speed camera. A Throttle rule lets the first matching notification through and then blocks the repeats for a while. Notifications that don't match the rule are not affected.

Choose Throttle as the rule type, set the title and text filters as usual, and then set how long repeats are blocked under Advanced Configuration, in seconds or minutes. It's one minute unless you change it. The Rules list shows each Throttle rule's rate, for example "At most one every 20 s".

  • To throttle one kind of notification, give the rule a filter that matches it, such as \d+ ?m\b as a Regex text filter for distance alerts like "900 m".
  • To throttle everything an app sends, leave both filters empty.

Notifications held back by a Throttle rule appear in the "Blocked" tab. The wait restarts only when a notification actually comes through, so a steady stream of repeats can't keep it going forever. Ongoing notifications that stay put, like a music player's, are never throttled.

8. Pre-built rules, backups and sharing

DoNotNotify comes with ready-made rules for many popular apps, which block their promotional and engagement notifications. When it finds one of those apps on your phone, it adds the rules automatically and tells you which apps it found. To add the others, tap Browse Pre-built Rules in the "Rules" tab.

More rule lists, made by other users, are collected in the DoNotNotify-rules repository (Settings → Get more rules). To use one, download its file and import it with Settings → Export/Import Rules. The same option backs up your own rules to a file, so you can restore them later or move them to a new phone.

Once a rule you made has blocked 25 notifications, its card offers to Share it with the community. Sharing opens GitHub in your browser with the rule filled into a new issue; nothing is posted until you submit it there.

9. The History and Blocked tabs

The "History" tab lists the notifications that came through, grouped by app, and the "Blocked" tab lists the ones your rules blocked, including repeats held back by Throttle rules. Notifications are kept for 5 days; you can change this in Settings → History retention. To keep an app out of the History tab altogether, expand it and tap Stop monitoring. Your rules still apply to it, and you can bring it back from the "Unmonitored Apps" section at the bottom of the tab.

When you tap a notification in DoNotNotify's history, you get the option to trigger the action associated with it. However, sometimes the "Open" button will not be available. This is because Android does not allow us to store this action (called an Intent) in our database, and it must be kept in memory. Hence, if the memory is cleared for some reason (app closure/reboot etc), then the "Open" button will not be available.

10. My notifications are not being blocked despite creating a rule!

First, check that the rule is on, and that its conditions hold: a rule limited to certain hours or to when your phone is in use does nothing the rest of the time. The All rules active switch at the top of the "Rules" tab must be on, too. If DoNotNotify isn't blocking anything at all, your phone may have shut it down: tap the "DoNotNotify isn't running" notification if you got one, and check that DoNotNotify still has notification access and unrestricted battery use.

If none of that is it, it is likely an unfortunate side-effect of a feature called Live Update Notifications. Android does not allow us to block notifications from apps that use this feature. You can spot these notifications by looking at the "Blocked" tab in DoNotNotify. These persistent/ongoing notifications will have a warning icon next to them.
